# Testing Second Shooter on Two iPhones

A step-by-step guide to installing, running, and testing the Second Shooter Expo app on two physical iPhones over the local network and over the internet.

> **Two physical iPhones are required.** WebRTC and vision-camera do not work in the iOS simulator, and the two halves of a pairing must run on real devices.

---

## Prerequisites

Make sure once per machine:

- **macOS** with **Xcode** installed (Xcode 15 or newer is what Expo SDK 54 expects). Open it once so the iOS toolchain is initialised.
- **Node.js 18+** and **npm**.
- **CocoaPods** (`sudo gem install cocoapods`, or `brew install cocoapods`). `npx expo run:ios` will run `pod install` for you, but the `pod` binary itself must be on `$PATH`.
- **Two iPhones**, both running iOS 16 or newer (the Expo 54 baseline). Cameras need to be real, so neither can be a simulator.
- **A USB‑C / Lightning cable** for the Mac → Camera‑phone link. The Remote phone only needs WiFi.

You also need the Firebase project described in `AGENTS.md` (Firestore + Anonymous auth + the `.env` below). TURN is only needed if the two phones will be on different networks; STUN is enough on the same WiFi.

---

## One-time setup (per machine)

### 1. Clone and install JS deps

```bash
git clone <your fork url> second-shooter
cd second-shooter
npm install
```

### 2. Fill in `.env`

Copy the example (create it from `AGENTS.md` if it isn't in the repo) and fill in the `EXPO_PUBLIC_FIREBASE_*` values from the Firebase console:

```bash
cp .env.example .env   # if the file isn't already present, create one — see AGENTS.md
# then edit .env
```

The file must contain at least:

```
EXPO_PUBLIC_FIREBASE_API_KEY=...
EXPO_PUBLIC_FIREBASE_AUTH_DOMAIN=...
EXPO_PUBLIC_FIREBASE_PROJECT_ID=...
EXPO_PUBLIC_FIREBASE_STORAGE_BUCKET=...
EXPO_PUBLIC_FIREBASE_MESSAGING_SENDER_ID=...
EXPO_PUBLIC_FIREBASE_APP_ID=...
```

Without these, `src/config/firebase.ts` will throw and the app will not get past the loading screen.

> **Anonymous auth must be enabled** in the Firebase console (Authentication → Sign-in method → Anonymous). The app signs in anonymously before touching Firestore.

### 3. Prebuild the native iOS project

`ios/` is gitignored and is generated by Expo. Generate it the first time you build:

```bash
npx expo prebuild --platform ios --clean
```

This produces `ios/SecondShooter.xcworkspace`, `ios/Podfile`, etc., from `app.json`. Re-run with `--clean` only when you intentionally want to start over — the normal rebuild path (`npx expo run:ios`) keeps `ios/` in sync incrementally.

### 4. Apple Developer signing (required for the camera & mic)

The dev client uses the camera, microphone, and local network, all of which require a valid provisioning profile. Open `ios/SecondShooter.xcworkspace` in Xcode, select the `SecondShooter` target → **Signing & Capabilities**, choose your **Team**, and change the **Bundle Identifier** to one tied to that team (the default `com.secondshooter.app` is fine if your team owns it). Without this the app installs but crashes the moment it touches the camera.

## First install on the camera iPhone

This iPhone is the one whose camera you'll be driving remotely. Plug it into the Mac.

```bash
npx expo run:ios --device "Your iPhone Name"
```

What this does, in order:

1. Runs `pod install` (first time only).
2. Compiles the native app with `react-native-vision-camera`, `react-native-webrtc`, etc.
3. Installs the dev client (`SecondShooter`) onto the iPhone.
4. Launches Metro and opens the app on the device.

The first build takes a few minutes; later ones are fast. When the build is done, grant **Camera**, **Microphone**, and **Photo Library** permissions on the iPhone when prompted — without them the app shows a black viewfinder.

> **Run `npx expo run:ios` again whenever you add or remove a native dependency** (`react-native-webrtc`, `expo-camera`, etc.) or change anything in `app.json`/`ios/`. A pure JS change does **not** need a rebuild — Metro hot-reloads it.

---

## Starting a development session

Once the dev client is installed, you don't need the cable for daily iteration — only for the *first* install and for new builds.

```bash
npx expo start --dev-client
```

The Camera iPhone, on the same WiFi as the Mac, picks up the dev server and reloads instantly on every JS change. If it doesn't connect automatically:

1. Open the **Second Shooter** app on the iPhone.
2. Tap **Enter URL manually** and paste the `exp://<your-mac-ip>:8081` URL Metro printed, or scan the QR code from the Metro terminal.

You can keep `npx expo start --dev-client` running for both phones (more on that below).

---

## Installing on the second iPhone (the remote)

The Remote iPhone doesn't need a cable — it just needs to reach the Metro dev server on the same WiFi.

### Option A: Expo Go (only for plain JS iteration)

If you've only changed JavaScript/TypeScript files (no native module changes), you can install **Expo Go** from the App Store and point it at the Metro URL. This skips the entire native build.

> Expo Go **does not** ship `react-native-vision-camera` or `react-native-webrtc`, so the Remote screen will crash the moment it tries to stream a preview. Only use this for UI-only changes.

### Option B: Build the dev client on the second iPhone (recommended)

For real pairing tests, both iPhones need the dev client:

```bash
npx expo run:ios --device "Second iPhone Name"
```

This compiles a second copy of the app. iOS does not allow two builds with the same Bundle ID on one Apple ID at the same time, so either:

- Use a different Bundle ID for the second build (`SecondShooter-dev` in `app.json` → `ios.bundleIdentifier` before re-running), or
- Unplug the first iPhone, build the second, then re-install the first when you want both online.

For a quick two-phone test, the simplest workflow is:

1. Build + install on **Phone A**.
2. Unplug A, build + install on **Phone B**.
3. Plug A back in and rebuild over B's install (Metro serves both — only the *native binary* needs to match the device).

If you only need one dev client on a single Mac + a Windows cert situation, both phones can point at the same Mac as long as they're on the same WiFi — Metro supports multiple clients.

## Running the two-phone test

On the **Camera iPhone** (the one whose lens you'll be driving):

1. Open Second Shooter.
2. The **Camera** screen appears with a QR code.
3. Note the URL under the QR code (`https://apps.binnyva.com/second-shooter/s/{sessionId}`).

On the **Remote iPhone**:

1. Open Second Shooter.
2. Tap **Remote** on the home screen.
3. Grant camera permission (used only for QR scanning).
4. Scan the QR code from the Camera iPhone — the app navigates to `Remote` with the session ID filled in.
5. Wait a few seconds. The status pill goes from `connecting` → `connected`. You should now see the Camera iPhone's viewfinder on the Remote iPhone.

If pairing hangs at `connecting`:

- Confirm both phones have internet (Firestore signaling goes via Firebase, not local WiFi).
- Confirm `.env` is filled in and the app was reloaded after editing it.
- Check the Mac's terminal — Firebase errors show up there.
- If both phones are on mobile data or different NATs, STUN may not punch a hole. See "When STUN isn't enough" below.

### What to try

- Tap the **shutter** on the Remote — the photo saves to the Camera iPhone.
- Pinch-zoom on the Remote — at 1x the preview switches to a true WebRTC video stream; above 1x it falls back to JPEG frames (a deliberate hybrid, see `AGENTS.md`).
- Switch to **video** mode on the Remote, start/stop recording.
- Use the **volume buttons** on the Camera phone as a physical shutter (toggle in Settings).

## When STUN isn't enough

If the two phones are on the same WiFi they connect directly. If they're on different networks (e.g. one on home WiFi, one on cellular, or both behind CGNAT), direct STUN often fails. The fallback is Cloudflare Realtime TURN, which mints short-lived credentials from the `getIceServers` Cloud Function (see `functions/`).

To deploy:

```bash
# In functions/
cp .env.example .env   # fill in CLOUDFLARE_TURN_TOKEN_ID
firebase functions:secrets:set CLOUDFLARE_TURN_API_TOKEN
firebase deploy --only functions
```

To prove TURN is actually being used, temporarily add `iceTransportPolicy: 'relay'` to both peer connections (`src/config/webrtc.ts` and `web-remote/src/lib/webrtc.ts`). Pairing then succeeding proves the relay path works.

## Releasing to TestFlight (optional)

For a longer test or a tester on another network:

```bash
eas build --platform ios --profile preview
```

`eas.json` is not yet in the repo; create one with `eas build:configure` first, or follow the Expo docs. The `.ipa` will be available in your Expo account for ad-hoc distribution.

## Troubleshooting checklist

| Symptom | Likely cause |
|---|---|
| Camera screen is black | Camera permission denied. iOS Settings → Second Shooter → Camera → On. |
| App crashes on launch after pulling new code | Native dep changed. Re-run `npx expo run:ios`. |
| `Error: No Firebase app initialized` | `.env` missing/empty. Edit and reload Metro (`r` in the terminal). |
| Pairing stuck at `connecting` | Firebase project missing Anonymous auth, or wrong `EXPO_PUBLIC_FIREBASE_PROJECT_ID`. |
| Preview works on same WiFi, fails over cellular | TURN not deployed, or `functions/.env` missing `CLOUDFLARE_TURN_TOKEN_ID`. |
| QR code on Camera phone, Remote phone scans but lands on web remote | Second phone doesn't have the app installed — that's the deep-link fallback working as designed. Install the dev client. |
| Volume buttons don't fire the shutter | The `useVolumeShutter` hook isn't enabled in the Settings screen. |

## Quick reference

```bash
# First build on a fresh clone
npm install
cp .env.example .env      # then fill in Firebase values
npx expo prebuild --platform ios
npx expo run:ios --device "Camera iPhone"

# Daily development (both phones on WiFi)
npx expo start --dev-client

# Rebuild only when native deps change
npx expo run:ios

# Unit tests (no device needed)
npm test
```
